# last-mile M1 Phase 1 (Core) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A headless, deterministic, fixed-point simulation of a 2-squad "Beacons" round, with agents driven by sandboxed Rhai reflexes. Every round is recorded as a header plus a stamped decision log and replays **bit-exact**.

**Architecture:** A Cargo workspace with three crates for this phase:
- `lm-core`: the pure simulation. No networking, rendering or floats. It holds fixed-point math, worldgen, LOS, Jump Point Search, decisions and stamping, lane conditioning, agents with intents and safe branches, `ScoreView` and menus, the Beacons rules, Rhai reflexes, the round log and the state hash.
- `lm-proto`: message types and the postcard codec. The QUIC transport comes in phase 3.
- `lm-tools`: the `lm` CLI that runs, replays, diffs and golden-checks rounds.

Reflexes run *inside* the sim on every node and are never logged. Only external decisions (human, System-1/2, tests) travel and are logged (D8, D10).

**Tech Stack:** Rust 1.99 (edition 2021), `serde` + `postcard` (log and wire), `rhai` (features `no_float`, `sync`), `thiserror`, `clap` (lm-tools only), `proptest` (dev).

**Spec:** [`docs/superpowers/specs/2026-10-28-last-mile-m1-design.md`](../specs/2026-10-28-last-mile-m1-design.md). Decisions D1–D48 are in [`docs/design/decisions.md`](../../design/decisions.md). The evidence behind the defaults is in [`docs/research/poc/`](../../research/poc/) (presence → D42, lead → D44, student → D47).

## Global Constraints

- **No floats in `lm-core`:** no `f32`/`f64` types, literals or `as` casts in `lm-core/src`. Enforced by `#![deny(clippy::float_arithmetic, clippy::float_cmp, clippy::cast_precision_loss)]` at the crate root, plus `scripts/check-no-float.sh` (a grep for `f32|f64` in `crates/lm-core/src`, failing on any hit).
- **No unordered containers in sim state:** no `HashMap`/`HashSet` in `lm-core` state or iteration. Use `BTreeMap`/`BTreeSet`/`Vec`. Also no wall clock, thread RNG or environment reads in `lm-core`.
- **Overflow is a bug, never silent:** `overflow-checks = true` in `[profile.release]` and `[profile.dev]`. Use explicit `wrapping_*` only where wrapping is intended (hashes, RNG).
- **Canonical bytes:** every hash is FNV-1a 64 over explicit **little-endian** encodings (never `transmute`, never in-memory layout).
- **Fixed-point units (spec §3):** 1 unit = 1/1024 m; chunk = 32 m = 32 768 units; `Pos { chunk: [i32;3], off: [i32;3] }` with `0 <= off < 32768` after `normalize()`; angles are `u16` (65 536 = full turn); trig is Q14 (16 384 = 1.0).
- **Dependency rule:** `lm-core` depends only on `serde`, `postcard`, `rhai`, `thiserror`. No Bevy, tokio, quinn or network crates in `lm-core` or `lm-proto`.
- **Every tunable lives in `Params`** with the spec §11 default. No magic numbers in sim code: a literal that tunes behaviour must be a `Params` field.
- **Toolchain:** `rust-toolchain.toml` pins `channel = "1.99"`. Develop and test in WSL. The ProArt-native build (`lm-host`) is phase 2.
- **Commits:** small and frequent, conventional prefixes (`feat:`, `test:`, `chore:`). Every commit message ends with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- **Determinism is the product.** A change that alters a golden hash must update `tests/golden.toml` in the same commit, with the reason in the message.

## Review Focus

1. **Bad seeds:** a worldgen seed that walls off a spawn or beacon must still yield a playable, connected map, never a crash or an unwinnable round → test `worldgen_always_connected` over 500 seeds (Task 3).
2. **Bad decisions:** a decision for an unknown agent, a duplicate `seq`, or an `apply_tick` so far in the past it's stale must be rejected deterministically with a named reason, never panic or apply → tests `rejects_unknown_source`, `rejects_duplicate_seq`, `stale_is_dropped` (Task 5).
3. **Hostile or broken reflex scripts:** an infinite loop, a runtime error, a parse error or a garbage return value must cost that agent its reflex for the tick and nothing else → tests `infinite_loop_runs_out_of_fuel`, `runtime_error_is_contained`, `garbage_return_is_refused`, `parse_error_fails_round_setup` (Task 10).
4. **Damaged logs:** a truncated, bit-flipped or wrong-version log file must fail replay with the exact segment named, never panic or silently replay a prefix → tests `truncated_log_names_segment`, `flipped_byte_breaks_chain`, `wrong_version_rejected` (Task 12).
5. **Nonsense parameters:** `tick_hz = 0`, a deadband outside 0..=65535, zero squads, a world smaller than a chunk, or `min_lead > max_lead` must be refused before a round starts with a message naming the field → test `validate_rejects_each_bad_field` (Task 2).

  **Stamping rule:** `arrived` is the first not-yet-simulated tick.
  - `apply_tick >= arrived` → on time, stamped at `apply_tick`.
  - Otherwise late: `late_by = arrived - apply_tick`. If `late_by > stale_window_ticks`, the result is `Reject::Stale`. Otherwise it's stamped at `arrived`.
  - `seq` must strictly increase per `Source`.

  **`drain(tick)` order:**
  - Sort by `(rot(source), seq)`, where `rot(Agent(i) | Human(i)) = (i + n - tick % n) % n` and `System` sorts first.
  - Within the same source, Human comes before Agent.

     - `ActionOn` sets `held`, and `ActionOff` clears it.
     - `Intent` calls `set_intent`.
     - `Lane` runs the agent's `LaneConditioner` for `gate`, then sets `held = None` and stores the selected `MenuOption` as the agent's lane command.

     - then `choose_cmd` and `move_step`.
  4. Run `ruleset.step` with the same rotated order.
  5. If `(t + 1) % hash_interval_ticks == 0`, set `hash = Some(state_hash())`. Then advance to t + 1.
- `state_hash` covers the tick, world, all agents in id order, the squad knowledge and the ruleset.
